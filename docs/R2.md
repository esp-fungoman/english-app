# Cloudflare R2: upload ảnh

Ứng dụng dùng bucket private. API ký URL; trình duyệt PUT trực tiếp lên R2 rồi lưu object key vào hồ sơ từ hoặc avatar. Khi hiển thị, `/api/media?key=...` cấp URL GET có hạn. Credentials chỉ nằm ở API, không dùng biến `NEXT_PUBLIC_*`.

Không cần migration database, Worker, custom domain hoặc public bucket cho luồng này. Hosting của Web/Admin/API là cấu hình riêng; tích hợp này chỉ thay nơi lưu ảnh.

## 1. Tạo bucket

Trong [Cloudflare Dashboard](https://dash.cloudflare.com/), mở **R2 object storage → Overview → Create bucket**. Đặt tên, ví dụ `english-app-media`, và tạo bucket. Giữ Public access tắt, không bật r2.dev hoặc custom domain. Với cấu hình mặc định dùng bucket không giới hạn jurisdiction; nếu chọn jurisdiction, lấy đúng S3 API endpoint ở phần thông tin bucket.

## 2. Tạo thông tin truy cập S3

Tại R2 Overview, trong **Account Details**, chọn **Manage** cạnh API Tokens. Tạo R2 API token, chọn **Object Read & Write**, giới hạn cho bucket vừa tạo. Chọn Account API token nếu tài khoản có quyền; User API token cũng được hỗ trợ.

Lưu **Access Key ID** và **Secret Access Key** từ màn hình kết quả. Secret chỉ hiển thị một lần. Không dùng Global API Key hoặc chép nguyên API Token value vào Secret Access Key. Account ID có trong thông tin account của Cloudflare.

Nguồn: [R2 authentication](https://developers.cloudflare.com/r2/api/tokens/).

## 3. Điền cấu hình API

Điền bốn giá trị thật vào `.env` tại thư mục gốc, hoặc environment variables của service API khi deploy:

```dotenv
R2_ACCOUNT_ID=<account-id>
R2_BUCKET_NAME=english-app-media
R2_ACCESS_KEY_ID=<access-key-id>
R2_SECRET_ACCESS_KEY=<secret-access-key>
```

Không đưa credentials vào frontend hoặc commit `.env`. File `.env` local đã có sẵn các trường trống; điền trực tiếp trong editor, không cần gửi secrets vào chat.

API tự dùng region `auto` và endpoint `https://<account-id>.r2.cloudflarestorage.com`. Nếu bucket có jurisdiction, thêm endpoint chính xác do Cloudflare cung cấp, ví dụ:

```dotenv
R2_ENDPOINT=https://<account-id>.eu.r2.cloudflarestorage.com
```

Endpoint không chứa bucket name, đường dẫn object hay query string. Không dùng custom media domain/r2.dev cho endpoint ký URL. Khi bất kỳ R2*\* nào có giá trị, API yêu cầu một bộ R2 hoàn chỉnh; không trộn thông tin R2 với BUCKET*\_. Khi toàn bộ R2\_\_ trống, cấu hình S3 cũ BUCKET\_\* vẫn được hỗ trợ.

Nguồn: [AWS SDK v3 với R2](https://developers.cloudflare.com/r2/examples/aws/aws-sdk-js-v3/), [giới hạn custom domain của presigned URLs](https://developers.cloudflare.com/r2/api/s3/presigned-urls/#custom-domains).

## 4. Thêm CORS vào bucket

Mở bucket → **Settings → CORS Policy → Add CORS policy**, chọn JSON. Sao chép nội dung `config/cloudflare/r2-cors.local.json`:

```json
[
  {
    "AllowedOrigins": ["http://localhost:3000", "http://localhost:3001"],
    "AllowedMethods": ["PUT", "GET", "HEAD"],
    "AllowedHeaders": ["Content-Type"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3600
  }
]
```

Sau đó Save. Đây là định dạng dành cho Cloudflare Dashboard; Wrangler dùng một định dạng cấu hình khác.

Khi deploy, thêm origin thật của Web và Admin vào AllowedOrigins, ví dụ `https://learn.example.com` và `https://admin.example.com`, không có path hoặc dấu `/` cuối. Danh sách CORS của API (`WEB_ORIGIN`, `ADMIN_ORIGIN`) và CORS của bucket là hai cấu hình riêng, đều cần đúng origin. Không cần thêm URL API vào bucket nếu chỉ Web/Admin gọi R2 từ trình duyệt.

Nguồn: [R2 CORS](https://developers.cloudflare.com/r2/buckets/cors/).

## 5. Khởi động lại API

Sau khi điền `.env`, dừng tiến trình API cũ rồi chạy lại từ thư mục gốc:

```bash
NX_DAEMON=false NX_ISOLATE_PLUGINS=false pnpm exec nx serve api --outputStyle=stream
```

Nhập đúng `WEB_ORIGIN` và `ADMIN_ORIGIN` khi deploy. Đặt credentials ở service API, không ở service Web/Admin.

## Luồng tích hợp

- Admin chọn JPG/PNG/WebP/GIF trong drawer và Lưu. `POST /api/admin/uploads/presign` trả `{ url, key, contentType, expiresIn }`; key mới dưới `uploads/vocabulary/`.
- Avatar dùng `POST /api/student/uploads/presign`; key vẫn dưới `uploads/avatars/{studentId}/`.
- URL PUT có hạn 10 phút và ký kèm Content-Type. Browser gửi đúng Content-Type trả về; không gửi cookie ứng dụng tới R2.
- PUT thành công mới lưu key vào database; lỗi PATCH vẫn giữ key để thử lưu lại mà không upload thêm.
- `/api/media` trả `{ url, key, expiresIn }` với URL GET hạn 1 giờ. API không cache JSON chứa URL đã ký; ảnh nằm trên R2, không đi qua server ứng dụng.
- AWS SDK chỉ tạo checksum khi operation yêu cầu, tránh ký checksum của body trống trước khi browser gửi file thật.
- Cấu hình thiếu/không hợp lệ trả 501 với thông báo kho ảnh chưa cấu hình. Việc tạo URL ký sẵn không xác minh bucket hoặc credentials có tồn tại.

## Giới hạn xác minh

Chỉ production build API, Admin, Web cho thay đổi này. Chưa tạo bucket, cấp token hoặc áp dụng CORS trên tài khoản Cloudflare; chưa thực hiện upload/download thật. Sau khi có credentials và bucket CORS, mới có thể xác nhận kết nối thực tế.

## Bảo vệ media

`/api/media` chỉ cấp URL cho key đã được tham chiếu trong Word hoặc avatar đã lưu của chính học sinh đang đăng nhập. Ảnh từ vựng công khai qua API, bucket vẫn private. Giao diện giới hạn 5 MiB; server chưa kiểm tra nội dung bytes/dung lượng thực tế của direct PUT. Endpoint presign chịu rate limit Redis. Request ghi vào API cần `X-App-Request: 1` và Origin hợp lệ; PUT lên R2 không gửi header này hoặc cookie ứng dụng. Xem [SECURITY.md](SECURITY.md).
